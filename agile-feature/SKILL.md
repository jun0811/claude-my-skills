# 애자일 기능 개발 워크플로우

설계 → 구현 → 테스트 → 결과 4단계를 순서대로 진행하며, 각 단계 산출물을 현재 프로젝트의 `.claude/tasks/<기능명>/`에 문서로 남긴다. 각 단계는 사용자 승인을 받은 뒤에만 다음 단계로 진행한다 (자동 진행 금지).

## 사용법

`/agile-feature <기능명>`

## 준비

1. 현재 프로젝트 루트 기준으로 `.claude/tasks/<기능명>/` 디렉토리가 없으면 생성한다.
2. 프로젝트 루트에 `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/CONVENTIONS.md`, `docs/TESTING.md` 등이 있으면 읽어서 이후 단계에서 프로젝트 고유 규칙(네이밍, 아키텍처 패턴, 테스트 명령어 등)으로 반영한다. 없으면 일반적인 소프트웨어 엔지니어링 관례를 기본값으로 쓴다.
3. 이 스킬은 git commit을 직접 수행하지 않는다. 각 단계 완료 시 "커밋은 직접 진행해주세요"라고 안내만 한다.

## Phase 1 — 설계 (`01-design.md`)

`superpowers:brainstorming` 스킬의 대화 방식을 그대로 따른다:
- 한 번에 질문 1개씩, 멀티초이스 우선
- 요구사항/제약조건을 충분히 이해했으면 2~3개 접근법을 장단점과 함께 제시하고 추천안을 명시
- 설계안을 200~300자 단위 섹션으로 나눠 제시하고, 매 섹션마다 사용자에게 맞는지 확인

문서 저장 경로만 오버라이드한다: `docs/plans/...`가 아니라 `.claude/tasks/<기능명>/01-design.md`에 저장.

포함 내용: 목적 / 요구사항 / 제약조건(관련 기존 문서 링크 포함) / 아키텍처 개요 / 데이터 흐름 / 에러 처리 방침.

**체크포인트**: "설계가 확정되었습니다. 구현 단계로 진행할까요?" — 승인 시에만 Phase 2로 진행.

## Phase 2 — 구현 (`02-implementation.md`)

`01-design.md`를 다시 읽고, `superpowers:writing-plans`로 단계별 구현 계획을 작성한다. 프로젝트 고유 컨벤션(자원 키 규칙, 상태 갱신 순서, 안티패턴 등)이 문서화되어 있다면 체크리스트로 포함시킨다.

계획을 사용자에게 확인받은 후 실제 코드를 작성한다 (`superpowers:executing-plans` 또는 `superpowers:subagent-driven-development` 활용 가능).

문서에는 구현 계획 + 실제 구현 요약(파일별 변경 내용)을 기록한다.

**체크포인트**: 구현 완료 후 "테스트 단계로 진행할까요?"

## Phase 3 — 테스트 (`03-test.md`)

`02-implementation.md`를 다시 읽고, `superpowers:test-driven-development` 원칙(레드-그린-리팩터)을 따른다. 프로젝트에 특화된 테스트 스킬이 있으면 함께 활용한다.

1. 정상 / 엣지 / 에러 케이스 시나리오 목록을 먼저 작성
2. 시나리오 기반으로 테스트 코드 작성 및 실행
3. 실행 결과(pass/fail, 발견된 버그 등)를 문서에 기록

테스트 실행 명령어는 프로젝트의 `CLAUDE.md`/`package.json`에서 확인한다 (하드코딩 금지).

**체크포인트**: 테스트 통과 확인 후 "결과 정리 단계로 진행할까요?"

## Phase 4 — 결과 (`04-result.md`)

1. `03-test.md`까지의 전체 변경 diff를 리뷰한다 (가능하면 code-reviewer류 서브에이전트 호출).
2. 아래 형식으로 정리한다:

```markdown
## 결과 – {기능명} ({오늘 날짜})

### 잘된 점
-

### 발견된 이슈 / 기술부채
-

### 다음 리팩토링 포인트
-

### 배운 점
-
```

3. 마지막에 사용자에게 묻는다: "이 중 기억해둘 만한 피드백/프로젝트 정보가 있으면 메모리에 저장할까요?" — 승인 시에만 관련 memory 파일을 작성한다 (자동 저장 금지).

## 공통 규칙

- 각 단계 시작 시 이전 단계 문서를 다시 읽어 컨텍스트를 유지한다.
- 프로젝트에 `CLAUDE.md`/`docs`가 없으면 일반적인 관례를 기본값으로 사용한다.
- 사용자가 특정 단계를 건너뛰라고 명시적으로 요청하면 해당 문서 작성은 생략할 수 있으나, 건너뛴 사실을 다음 단계 문서에 기록한다.
- 한국어로 작성한다.
